# Decisions

## 2026-10-02 — Architecture
- Markdown is the only stored form; WYSIWYG DOM is the working copy while typing and is
  serialised after each edit. Source mode keeps text verbatim.
- Mentions are chips (`scheme:kind/id?refs`). A person who exists in two systems is ONE
  chip carrying both ids in `refs`, so a single mention can fan out to both. The library
  never knows the systems' names; hosts decide.
- Raw HTML is never interpreted. Links/images are filtered by a scheme allow-list.
- Emoji: the OS panel cannot be opened by a page; the button shows the shortcut.
- TypeScript is pinned to 5.x to match the sibling packages and tsup 8's declaration build. 7.x (the native compiler, `latest` on npm) has NOT been tested with tsup here; try it later.

## 2026-10-02 — features (upload policy, uploaders, mentions, paste)

**Mention / chip wire grammar** (implemented by `mentionHref` / `parseMentionHref` in `src/features/mentions.ts`; the parser module must accept exactly this):

```
href  := scheme ":" [ kind "/" ] id [ "?" pair { "&" pair } ]
pair  := key [ "=" value ]
```
- `scheme` is a letter followed by letters, digits, `+`, `.` or `-`; lower-cased on parse. `http`, `https`, `mailto`, `tel`, `sms`, `javascript`, `vbscript`, `data`, `file`, `ftp`, `blob`, `ws`, `wss`, `about`, `view-source` are never chip schemes. `scheme:` followed by `//` is not a chip.
- `kind`, `id`, `key`, `value` are each percent-encoded with `encodeURIComponent` PLUS `! ' ( ) *` (so the href is safe inside a Markdown link destination and never contains whitespace, brackets, quotes, backslash or backtick).
- `kind` is omitted together with its `/` when empty: `mention:u1`. When present, `kind` is everything before the FIRST raw `/`; `id` is everything after it (raw slashes tolerated on parse, always `%2F` on write).
- `id` must be non-empty; keys with no `=` parse as `""`; empty keys and empty pairs are skipped; the value is split at the FIRST `=`.
- Any malformed percent sequence makes the whole href not a chip (`null`), the parser then treats it as an ordinary link.
- Attribute order is insertion order; `attrs` is omitted from the parsed object when empty.
- The visible `@` is NOT in the href; it is the chip's `trigger`, stored in the link text (`[@Jane](mention:person/u1)`).

**Upload policy**
- `validateFile` order: disabled, too-many, empty, extension-denied, extension-not-allowed, mime-denied, mime-not-allowed, too-large. `countInBatch` is the number already accepted in this drop; the file is rejected once it reaches `maxFiles`.
- Extension rule: every dot-segment after the stem is checked against the deny list (`evil.php.jpg` is rejected). Cost: `my.app.txt` is rejected too, because `app` is denied. The allow-list matches the last segment only. Trailing dots/spaces are ignored because Windows ignores them. A MIME allow-list rejects an empty browser-reported type.
- `urlAllowed` checks the URL as written, entity-decoded and percent-decoded, each stripped of whitespace, controls, zero-width and bidi characters; all forms must pass. `\` is treated as `/`. `javascript:`/`vbscript:` are refused even if listed. `data:` needs the policy to list `data`, kind `image`, and `data:image/(png|jpeg|gif|webp);base64,`. Hosts compare the parsed hostname, never substrings; `*.example.com` matches subdomains only.
- Protocol-relative URLs (`//host`) are governed by BOTH `allowRelative` and `allowedHosts`.

**Uploaders**: PUT uses `fetch` (no real progress; reports `1` at the end); form and presigned use `XMLHttpRequest` for progress and abort. Image dimensions are added with a best-effort `probeImage` (3 s timeout). `createDataUrlUploader` is dev/demo only because it inlines the file into the Markdown.

**Mentions controller**: the editable keeps its own role; the controller adds `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant` (restoring/removing them on close/destroy). Escape stops propagation only while the menu is open, so a surrounding dialog still closes on the next Escape. The first query for a new mention is immediate, later keystrokes are debounced (default 100 ms). A menu positioned with `position: fixed` flips above the caret when it would overflow the viewport. One `MentionOptions` entry per trigger string. Class hooks for the stylesheet: `atm-mention-menu`, `-list`, `-option`, `-avatar`, `-body`, `-label`, `-desc`, `-badge`, `-group`, `-status`, `-live`; rows with a colour set `--atm-chip-color`.

**Paste**: `htmlToMarkdown` parses with `DOMParser` (inert), converts in one tree walk, and escapes `* _ \` [ ] $ ~ & |` and line-start `# - + * > 1.` only where they would be read as Markdown. Links keep http/https/mailto/tel (no relative URLs unless the policy allows them); images keep http(s) only. Navigation, ads (class/id tokens such as `ad`, `advert`, `sponsored`, `newsletter`, `share`, `social`), forms controls, hidden elements and Office/Google wrappers are dropped. Adjacent lists are separated by alternating markers (`-`/`*`, `.`/`)`) so they do not merge. `looksLikeMarkdown` needs a closed fence, or two independent signals over two or more lines.

## 2026-10-02 — Math (src/math)
- Output is MathML Core, one `<math display="inline|block"><semantics>…<annotation encoding="application/x-tex">` per call. Browsers render it natively; there is no font or CSS dependency. The conversion is a pure function (no DOM), so it runs on the server.
- Escaping: every text node, the annotation and every attribute value goes through one `esc()`. No user string is ever placed in an attribute: colour and size commands were left out on purpose, so every attribute value is a constant.
- Fonts (`\mathbf`, `\mathbb`, `\mathcal`, `\mathfrak`, `\mathsf`, `\mathtt`) map letters to Unicode Mathematical Alphanumeric code points, because MathML Core dropped `mathvariant` other than `normal`. Letters that live in Letterlike Symbols (ℝ, ℒ, ℭ …) are listed as exceptions.
- Failure policy: an unknown command becomes `<merror><mtext>\name</mtext></merror>` and parsing continues. Unbalanced braces, a missing argument, stray `&`, `\right` or `\end` degrade to empty or are skipped. Only two things stop the whole formula, and both yield one `<merror>` and never an exception: input over 20,000 characters, and nesting deeper than 64 (also bounds recursion depth, so `\sqrt\sqrt\sqrt…` cannot overflow the stack).
- Macros are expanded textually before parsing, with a 500-expansion and 50,000-character cap, so `\a → \a\a` and exponential towers terminate; anything left unexpanded shows up as `<merror>`. Macro names are letters only; lookups use a `Map`, and symbol tables have a null prototype, so `\constructor` and `\toString` are just unknown commands.
- Limits (`\sum_a^b`) are placed under/over only when `display` is true (or after `\limits`); `\int` family always uses side scripts. `\underbrace`/`\overbrace` always take limits above/below.
- Size budget (5 kB gzip) forced cuts. Not supported, by choice: `\big`/`\Big` size commands, `\textcolor`/`\color`, `\phantom`, infix `\over`/`\choose`, `\not`, `\boxed`, `\cancel`, `\tag`, `\substack`, `\Bmatrix`/`\Vmatrix`, `\scriptstyle`, and the rarer symbols. Adding them back costs about 40–80 bytes each; the budget has about 40 bytes of headroom, so add something only by removing something.
- `\begin{cases}`/`aligned`/`array` column alignment is emitted as `style="text-align:left|right"` on `<mtd>` (the `columnalign` attribute is not in MathML Core). A host with a strict `style-src` CSP that blocks inline style attributes will see centred cells.

## 2026-10-02 — Highlight (src/highlight)
- Engine: rules are recompiled with the sticky flag (and `g`/`y` stripped from the input), so a rule can only match exactly at the cursor. First matching rule wins. A zero-length match is treated as "no match" for that rule, so the scan always advances. Work cap 200,000 characters per call; the rest is emitted as escaped plain text.
- Every language rule list must be linear: no unbounded look-ahead, no rule that can fail after scanning to the end of input and retry at the next character. Unterminated strings and comments therefore match to the end of the line (strings) or input (block comments) instead of failing. A sweep test runs 100,000 of each hostile character, and of hostile pairs, through every language (< 400 ms asserted; < 200 ms for the JS cases the brief names).
- Extension to `TokenRule`: `token: ""` means "consume this text as plain". Languages use it for identifiers and whitespace so the scanner takes one step per word instead of one failed rule attempt per character. No type change was needed.
- Template literals: `${…}` is kept inside the string token (one nested brace level, nested template literals allowed). Expressions inside it are not highlighted separately; the engine has no state and states were not worth the bytes.
- JS regex-vs-division is decided with look-behind (previous token is a word, `)` or `]` → division; keyword such as `return` → regex). Look-behind is ES2018; Every language except JSON and SQL uses look-behind; Safari before 16.4 throws when such a rule is compiled, so the highlighter cannot register them there.
- JSX/HTML tags in JS are recognised heuristically (`<Name` not directly after a word, `)` or `]`; any `</Name`). `a<b` and `i<n;` are not tags.
- Markdown, YAML and bash are line-oriented approximations, not parsers: a YAML block scalar's body is highlighted as if it were mapping keys; Markdown does not nest emphasis inside links.
- `src/highlight/langs/_shared.ts` holds the JS/TS rule builder and the `word()`/`alt()` helpers. The bundler emits it as a shared chunk, so it is not counted against any one language's budget. Each language is ~0.3–1.0 kB gzip including the helper.
- `src/styles/highlight.css`: colours are fallbacks inside `var(--atm-tok-*, …)`, never declared on `:root`, so a variable defined on any ancestor or on the page overrides the theme in both light and dark.

## 2026-10-02 — Parser and renderer (src/parser, src/render)
- **Hand-written, line-based block parser; linked-list inline parser.** Containers (quote, list item, footnote body, `:::` block) are parsed by collecting their lines and recursing, with lazy continuation decided by parsing the collected lines and asking whether the deepest last block is a paragraph. The inline pass uses the CommonMark delimiter-stack algorithm on doubly linked lists so a 100k-character paragraph stays linear. A 200 kB document parses in ~30 ms.
- **Inline content is deferred.** The block pass queues `[children[], text]` pairs; inline parsing runs once every reference definition and footnote label is known. Reference links resolve into plain `link` nodes, definitions disappear from the Doc.
- **`stringify` is idempotent by construction, then verified.** Text is escaped conservatively (backslash, backtick, `*`, `~`, `[`, `]`, non-intraword `_`, autolink-shaped `<`, entity-shaped `&`, `|` where a table could form, `$` when two or more occur in one run of inline content, line-start markers). Escaping alone is not a proof, so `stringify` re-parses its output and re-serialises until the text stops changing (max 4 passes): the result is a fixed point, which makes `stringify(parse(stringify(parse(x)))) === stringify(parse(x))` true for every x, including hand-built Docs from the editor. `stringify(doc, { stable: false })` skips the loop (one pass) for hot paths where the Doc came straight from `parse`; on 20 000 random inputs a single pass is already a fixed point for 99.5 %.
- **Tight lists** are only emitted tight when every pair of sibling blocks inside an item survives a missing blank line (paragraph followed by a paragraph would merge); otherwise the whole list is emitted loose. Adjacent lists alternate marker (`-`/`*`, `.`/`)`) so they do not merge on re-parse.
- **Bare URLs.** A link whose text equals its href is emitted bare (`http://x.com`, `www.x.com`) when the neighbours cannot extend it, otherwise as `<http://x.com>`. Text that merely looks like a bare URL is protected with `http\://` / `www\.`.
- **Math.** `$x$` needs a non-space after the opener, a non-space before the closer and no digit after the closer; `$5 and $6` stays text. A failed scan is remembered per run length so a paragraph of dollar signs is linear. Block `$$` must be closed (an unclosed `$$` is plain text, unlike a code fence). `$$x$$` inside a line is inline math.
- **Chips.** Parse accepts `scheme:kind/id?k=v` and `scheme:id`, every part percent-decoded; the trigger is the first code point of the link text when it is not a letter, number or space. Stringify percent-encodes everything `encodeURIComponent` does plus `! ' ( ) *`. A chip's label is plain text; formatting inside the link text is dropped.
- **Custom inline syntax.** Declarative `open`/`close` search for the closer skipping escapes and code spans. When `open === close` the opener must be followed, and the closer preceded, by non-space, and a run of the marker character must be exactly as long as the marker, so `===`, `====` and `a == b` stay text. A failed search disables that syntax for the rest of the paragraph. Regex `pattern` syntaxes are searched with a global copy of the regex (sticky flag removed) and may return named groups, which become `data`.
- **Pattern syntaxes cannot be inverted**, so the matched source is kept in `data._raw` and stringify emits it verbatim. Editing the node's children therefore does not change the markdown for a pattern-only syntax. **Idea:** an additive `serialize?(children, data) => string` on `InlineSyntax` in types.ts would fix this; not done because types.ts belongs to the contract owner. `_raw` (any `_`-prefixed data key) is never rendered.
- **Custom block syntax.** `::: name key=value key2="two words"` … `:::`; nested openers of registered names are counted, so inner `:::` closes the inner block. An unclosed container is plain text. Fence is configurable per syntax.
- **Renderer** builds one small virtual tree (`{t, a, c}` / text / trusted raw / DOM element) and has two serialisers: a string one for `renderHtml` and a `createElement`/`setAttribute`/`createTextNode` one for `renderDom`. Both outputs are therefore structurally identical (tested). The only `innerHTML` use is a `<template>` for markup returned by `highlight.highlight` and a string-returning `mathRenderer`/`ChipDefinition.render`: that markup is trusted by contract, user text never goes through it.
- **Link policy.** Scheme sniffing strips control characters, spaces and zero-width characters first (`java\tscript:`). `javascript:`, `data:` and `vbscript:` are refused even if the host lists them in `allowedSchemes` (this includes `data:` images; hosts that upload via data URLs must store them elsewhere or rely on `resolve`). `resolve` runs after the check and its result is checked again (scheme only), so it cannot smuggle `javascript:` in. `allowedHosts` accepts exact hosts and `*.suffix`, applies to http(s) and protocol-relative URLs. `rel`/`target` are only set on http(s)/`//` links.
- **Custom element attributes.** Names must match `/^[a-z][a-z0-9-]*$/`, never start with `on`, `srcset` is dropped, `style` values containing `url(`, `expression`, `javascript`, `@import`, `<`, `>` are dropped, URL-valued attributes (`href`, `src`, `action`, `formaction`, `poster`, `cite`, `data`, `background`, `ping`, ...) go through the link policy. `data` from pattern groups is rendered as `data-<key>`.
- **Render extras beyond the contract.** Chips carry `data-scheme`, `data-kind`, `data-id`, `data-trigger` and `data-refs` (JSON of `attrs`) so the editor surface can rebuild the node from the DOM; the palette colour is `--<prefix>-chip-color: var(--<prefix>-chip-N)` (N 1-8) or a literal colour that passes a conservative character whitelist. Lists get `atm-tight` when tight and tight items render paragraphs without `<p>`. Footnote definitions are moved into a `<section class="atm-footnotes">` at the end; references without a definition render as literal text.
- **Footnote references need a definition** to parse as `footnoteRef`; otherwise `[^x]` is text (matches GFM and keeps stringify stable).
- **Limits.** Container nesting is capped at 40 levels (deeper content becomes paragraph text) and emphasis nesting at 64, so hostile input cannot overflow the stack in parse, stringify, render or walk. NUL becomes U+FFFD. Entities: all numeric ones plus ~35 common named ones (amp, lt, gt, quot, nbsp, copy, hellip, mdash, ...), to stay inside the size budget; unknown names stay literal.
- **Not supported (by design in 0.x).** Raw HTML, link reference definitions inside setext headings, tables that interrupt a paragraph (GFM allows it; here the header row must start a block), email bare autolinks (`a@b.c` without angle brackets), `<` autolinks with schemes other than `scheme:` + non-space, emphasis with `~` runs other than exactly two.

# Decisions

## 2026-10-02 — Architecture
- Markdown is the only stored form; WYSIWYG DOM is the working copy while typing and is
  serialised after each edit. Source mode keeps text verbatim.
- Mentions are chips (`scheme:kind/id?refs`). A person who exists in two systems is ONE
  chip carrying both ids in `refs`, so a single mention can fan out to both. The library
  never knows the systems' names; hosts decide.
- Raw HTML is never interpreted. Links/images are filtered by a scheme allow-list.
- Emoji: the OS panel cannot be opened by a page; the button shows the shortcut.
- TypeScript is pinned to 5.x to match the sibling packages and tsup 8's declaration build. 7.x (the native compiler, `latest` on npm) has NOT been tested with tsup here; try it later.

## 2026-10-02 — features (upload policy, uploaders, mentions, paste)

**Mention / chip wire grammar** (implemented by `mentionHref` / `parseMentionHref` in `src/features/mentions.ts`; the parser module must accept exactly this):

```
href  := scheme ":" [ kind "/" ] id [ "?" pair { "&" pair } ]
pair  := key [ "=" value ]
```
- `scheme` is a letter followed by letters, digits, `+`, `.` or `-`; lower-cased on parse. `http`, `https`, `mailto`, `tel`, `sms`, `javascript`, `vbscript`, `data`, `file`, `ftp`, `blob`, `ws`, `wss`, `about`, `view-source` are never chip schemes. `scheme:` followed by `//` is not a chip.
- `kind`, `id`, `key`, `value` are each percent-encoded with `encodeURIComponent` PLUS `! ' ( ) *` (so the href is safe inside a Markdown link destination and never contains whitespace, brackets, quotes, backslash or backtick).
- `kind` is omitted together with its `/` when empty: `mention:u1`. When present, `kind` is everything before the FIRST raw `/`; `id` is everything after it (raw slashes tolerated on parse, always `%2F` on write).
- `id` must be non-empty; keys with no `=` parse as `""`; empty keys and empty pairs are skipped; the value is split at the FIRST `=`.
- Any malformed percent sequence makes the whole href not a chip (`null`), the parser then treats it as an ordinary link.
- Attribute order is insertion order; `attrs` is omitted from the parsed object when empty.
- The visible `@` is NOT in the href; it is the chip's `trigger`, stored in the link text (`[@Jane](mention:person/u1)`).

**Upload policy**
- `validateFile` order: disabled, too-many, empty, extension-denied, extension-not-allowed, mime-denied, mime-not-allowed, too-large. `countInBatch` is the number already accepted in this drop; the file is rejected once it reaches `maxFiles`.
- Extension rule: every dot-segment after the stem is checked against the deny list (`evil.php.jpg` is rejected). Cost: `my.app.txt` is rejected too, because `app` is denied. The allow-list matches the last segment only. Trailing dots/spaces are ignored because Windows ignores them. A MIME allow-list rejects an empty browser-reported type.
- `urlAllowed` checks the URL as written, entity-decoded and percent-decoded, each stripped of whitespace, controls, zero-width and bidi characters; all forms must pass. `\` is treated as `/`. `javascript:`/`vbscript:` are refused even if listed. `data:` needs the policy to list `data`, kind `image`, and `data:image/(png|jpeg|gif|webp);base64,`. Hosts compare the parsed hostname, never substrings; `*.example.com` matches subdomains only.
- Protocol-relative URLs (`//host`) are governed by BOTH `allowRelative` and `allowedHosts`.

**Uploaders**: PUT uses `fetch` (no real progress; reports `1` at the end); form and presigned use `XMLHttpRequest` for progress and abort. Image dimensions are added with a best-effort `probeImage` (3 s timeout). `createDataUrlUploader` is dev/demo only because it inlines the file into the Markdown.

**Mentions controller**: the editable keeps its own role; the controller adds `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant` (restoring/removing them on close/destroy). Escape stops propagation only while the menu is open, so a surrounding dialog still closes on the next Escape. The first query for a new mention is immediate, later keystrokes are debounced (default 100 ms). A menu positioned with `position: fixed` flips above the caret when it would overflow the viewport. One `MentionOptions` entry per trigger string. Class hooks for the stylesheet: `atm-mention-menu`, `-list`, `-option`, `-avatar`, `-body`, `-label`, `-desc`, `-badge`, `-group`, `-status`, `-live`; rows with a colour set `--atm-chip-color`.

**Paste**: `htmlToMarkdown` parses with `DOMParser` (inert), converts in one tree walk, and escapes `* _ \` [ ] $ ~ & |` and line-start `# - + * > 1.` only where they would be read as Markdown. Links keep http/https/mailto/tel (no relative URLs unless the policy allows them); images keep http(s) only. Navigation, ads (class/id tokens such as `ad`, `advert`, `sponsored`, `newsletter`, `share`, `social`), forms controls, hidden elements and Office/Google wrappers are dropped. Adjacent lists are separated by alternating markers (`-`/`*`, `.`/`)`) so they do not merge. `looksLikeMarkdown` needs a closed fence, or two independent signals over two or more lines.

## 2026-10-02 — Math (src/math)
- Output is MathML Core, one `<math display="inline|block"><semantics>…<annotation encoding="application/x-tex">` per call. Browsers render it natively; there is no font or CSS dependency. The conversion is a pure function (no DOM), so it runs on the server.
- Escaping: every text node, the annotation and every attribute value goes through one `esc()`. No user string is ever placed in an attribute: colour and size commands were left out on purpose, so every attribute value is a constant.
- Fonts (`\mathbf`, `\mathbb`, `\mathcal`, `\mathfrak`, `\mathsf`, `\mathtt`) map letters to Unicode Mathematical Alphanumeric code points, because MathML Core dropped `mathvariant` other than `normal`. Letters that live in Letterlike Symbols (ℝ, ℒ, ℭ …) are listed as exceptions.
- Failure policy: an unknown command becomes `<merror><mtext>\name</mtext></merror>` and parsing continues. Unbalanced braces, a missing argument, stray `&`, `\right` or `\end` degrade to empty or are skipped. Only two things stop the whole formula, and both yield one `<merror>` and never an exception: input over 20,000 characters, and nesting deeper than 64 (also bounds recursion depth, so `\sqrt\sqrt\sqrt…` cannot overflow the stack).
- Macros are expanded textually before parsing, with a 500-expansion and 50,000-character cap, so `\a → \a\a` and exponential towers terminate; anything left unexpanded shows up as `<merror>`. Macro names are letters only; lookups use a `Map`, and symbol tables have a null prototype, so `\constructor` and `\toString` are just unknown commands.
- Limits (`\sum_a^b`) are placed under/over only when `display` is true (or after `\limits`); `\int` family always uses side scripts. `\underbrace`/`\overbrace` always take limits above/below.
- Size budget (5 kB gzip) forced cuts. Not supported, by choice: `\big`/`\Big` size commands, `\textcolor`/`\color`, `\phantom`, infix `\over`/`\choose`, `\not`, `\boxed`, `\cancel`, `\tag`, `\substack`, `\Bmatrix`/`\Vmatrix`, `\scriptstyle`, and the rarer symbols. Adding them back costs about 40–80 bytes each; the budget has about 40 bytes of headroom, so add something only by removing something.
- `\begin{cases}`/`aligned`/`array` column alignment is emitted as `style="text-align:left|right"` on `<mtd>` (the `columnalign` attribute is not in MathML Core). A host with a strict `style-src` CSP that blocks inline style attributes will see centred cells.

## 2026-10-02 — Highlight (src/highlight)
- Engine: rules are recompiled with the sticky flag (and `g`/`y` stripped from the input), so a rule can only match exactly at the cursor. First matching rule wins. A zero-length match is treated as "no match" for that rule, so the scan always advances. Work cap 200,000 characters per call; the rest is emitted as escaped plain text.
- Every language rule list must be linear: no unbounded look-ahead, no rule that can fail after scanning to the end of input and retry at the next character. Unterminated strings and comments therefore match to the end of the line (strings) or input (block comments) instead of failing. A sweep test runs 100,000 of each hostile character, and of hostile pairs, through every language (< 400 ms asserted; < 200 ms for the JS cases the brief names).
- Extension to `TokenRule`: `token: ""` means "consume this text as plain". Languages use it for identifiers and whitespace so the scanner takes one step per word instead of one failed rule attempt per character. No type change was needed.
- Template literals: `${…}` is kept inside the string token (one nested brace level, nested template literals allowed). Expressions inside it are not highlighted separately; the engine has no state and states were not worth the bytes.
- JS regex-vs-division is decided with look-behind (previous token is a word, `)` or `]` → division; keyword such as `return` → regex). Look-behind is ES2018; Every language except JSON and SQL uses look-behind; Safari before 16.4 throws when such a rule is compiled, so the highlighter cannot register them there.
- JSX/HTML tags in JS are recognised heuristically (`<Name` not directly after a word, `)` or `]`; any `</Name`). `a<b` and `i<n;` are not tags.
- Markdown, YAML and bash are line-oriented approximations, not parsers: a YAML block scalar's body is highlighted as if it were mapping keys; Markdown does not nest emphasis inside links.
- `src/highlight/langs/_shared.ts` holds the JS/TS rule builder and the `word()`/`alt()` helpers. The bundler emits it as a shared chunk, so it is not counted against any one language's budget. Each language is ~0.3–1.0 kB gzip including the helper.
- `src/styles/highlight.css`: colours are fallbacks inside `var(--atm-tok-*, …)`, never declared on `:root`, so a variable defined on any ancestor or on the page overrides the theme in both light and dark.

## 2026-10-02 — Parser and renderer (src/parser, src/render)
- **Hand-written, line-based block parser; linked-list inline parser.** Containers (quote, list item, footnote body, `:::` block) are parsed by collecting their lines and recursing, with lazy continuation decided by parsing the collected lines and asking whether the deepest last block is a paragraph. The inline pass uses the CommonMark delimiter-stack algorithm on doubly linked lists so a 100k-character paragraph stays linear. A 200 kB document parses in ~30 ms.
- **Inline content is deferred.** The block pass queues `[children[], text]` pairs; inline parsing runs once every reference definition and footnote label is known. Reference links resolve into plain `link` nodes, definitions disappear from the Doc.
- **`stringify` is idempotent by construction, then verified.** Text is escaped conservatively (backslash, backtick, `*`, `~`, `[`, `]`, non-intraword `_`, autolink-shaped `<`, entity-shaped `&`, `|` where a table could form, `$` when two or more occur in one run of inline content, line-start markers). Escaping alone is not a proof, so `stringify` re-parses its output and re-serialises until the text stops changing (max 4 passes): the result is a fixed point, which makes `stringify(parse(stringify(parse(x)))) === stringify(parse(x))` true for every x, including hand-built Docs from the editor. `stringify(doc, { stable: false })` skips the loop (one pass) for hot paths where the Doc came straight from `parse`; on 20 000 random inputs a single pass is already a fixed point for 99.5 %.
- **Tight lists** are only emitted tight when every pair of sibling blocks inside an item survives a missing blank line (paragraph followed by a paragraph would merge); otherwise the whole list is emitted loose. Adjacent lists alternate marker (`-`/`*`, `.`/`)`) so they do not merge on re-parse.
- **Bare URLs.** A link whose text equals its href is emitted bare (`http://x.com`, `www.x.com`) when the neighbours cannot extend it, otherwise as `<http://x.com>`. Text that merely looks like a bare URL is protected with `http\://` / `www\.`.
- **Math.** `$x$` needs a non-space after the opener, a non-space before the closer and no digit after the closer; `$5 and $6` stays text. A failed scan is remembered per run length so a paragraph of dollar signs is linear. Block `$$` must be closed (an unclosed `$$` is plain text, unlike a code fence). `$$x$$` inside a line is inline math.
- **Chips.** Parse accepts `scheme:kind/id?k=v` and `scheme:id`, every part percent-decoded; the trigger is the first code point of the link text when it is not a letter, number or space. Stringify percent-encodes everything `encodeURIComponent` does plus `! ' ( ) *`. A chip's label is plain text; formatting inside the link text is dropped.
- **Custom inline syntax.** Declarative `open`/`close` search for the closer skipping escapes and code spans. When `open === close` the opener must be followed, and the closer preceded, by non-space, and a run of the marker character must be exactly as long as the marker, so `===`, `====` and `a == b` stay text. A failed search disables that syntax for the rest of the paragraph. Regex `pattern` syntaxes are searched with a global copy of the regex (sticky flag removed) and may return named groups, which become `data`.
- **Pattern syntaxes cannot be inverted**, so the matched source is kept in `data._raw` and `stringify` writes it back verbatim UNLESS the syntax has `serialize(inner, data)`: then `stringify` calls it (data keys starting with `_` are stripped, `inner` is the children as inline Markdown, a throw falls back to `_raw`). `_raw` (any `_`-prefixed data key) is never rendered. The dom-to-doc `_raw` workaround is gone.
- **Custom block syntax.** `::: name key=value key2="two words"` … `:::`; nested openers of registered names are counted, so inner `:::` closes the inner block. An unclosed container is plain text. Fence is configurable per syntax.
- **Renderer** builds one small virtual tree (`{t, a, c}` / text / trusted raw / DOM element) and has two serialisers: a string one for `renderHtml` and a `createElement`/`setAttribute`/`createTextNode` one for `renderDom`. Both outputs are therefore structurally identical (tested). The only `innerHTML` use is a `<template>` for markup returned by `highlight.highlight` and a string-returning `mathRenderer`/`ChipDefinition.render`: that markup is trusted by contract, user text never goes through it.
- **Link policy.** Scheme sniffing strips control characters, spaces and zero-width characters first (`java\tscript:`). `javascript:`, `data:` and `vbscript:` are refused even if the host lists them in `allowedSchemes` (this includes `data:` images; hosts that upload via data URLs must store them elsewhere or rely on `resolve`). `resolve` runs after the check and its result is checked again (scheme only), so it cannot smuggle `javascript:` in. `allowedHosts` accepts exact hosts and `*.suffix`, applies to http(s) and protocol-relative URLs. `rel`/`target` are only set on http(s)/`//` links.
- **Custom element attributes.** Names must match `/^[a-z][a-z0-9-]*$/`, never start with `on`, `srcset` is dropped, `style` values containing `url(`, `expression`, `javascript`, `@import`, `<`, `>` are dropped, URL-valued attributes (`href`, `src`, `action`, `formaction`, `poster`, `cite`, `data`, `background`, `ping`, ...) go through the link policy. `data` from pattern groups is rendered as `data-<key>`.
- **Render extras beyond the contract.** Chips carry `data-scheme`, `data-kind`, `data-id`, `data-trigger` and `data-refs` (JSON of `attrs`) so the editor surface can rebuild the node from the DOM; the palette colour is `--<prefix>-chip-color: var(--<prefix>-chip-N)` (N 1-8) or a literal colour that passes a conservative character whitelist. Lists get `atm-tight` when tight and tight items render paragraphs without `<p>`. Footnote definitions are moved into a `<section class="atm-footnotes">` at the end; references without a definition render as literal text.
- **Footnote references need a definition** to parse as `footnoteRef`; otherwise `[^x]` is text (matches GFM and keeps stringify stable).
- **Limits.** Container nesting is capped at 40 levels (deeper content becomes paragraph text) and emphasis nesting at 64, so hostile input cannot overflow the stack in parse, stringify, render or walk. NUL becomes U+FFFD. Entities: all numeric ones plus ~35 common named ones (amp, lt, gt, quot, nbsp, copy, hellip, mdash, ...), to stay inside the size budget; unknown names stay literal.
- **Not supported (by design in 0.x).** Raw HTML, link reference definitions inside setext headings, tables that interrupt a paragraph (GFM allows it; here the header row must start a block), email bare autolinks (`a@b.c` without angle brackets), `<` autolinks with schemes other than `scheme:` + non-space, emphasis with `~` runs other than exactly two.

## 2026-10-02 — Link previews and embeds (src/features/link-preview.ts, embeds.ts, styles/link-preview.css)
- **Hydration contract (the editor and the renderer implement this).** A paragraph whose only content is one link with text equal to its href (`findStandaloneUrl(block)` in embeds.ts decides) is emitted with the attribute `data-atm-standalone-link` (value: the URL, or empty to use the first `a[href]` inside). A bare anchor may instead carry `data-atm-preview-candidate`. `controller.hydrate(root)` writes `data-atm-preview-state` (`loading` | `done` | `none` | `skipped`) and `data-atm-preview-url` on the node and inserts the card (`contenteditable="false"`, `data-atm-preview-card`) as its next sibling. The source node stays in the DOM; `hydrate(root, { replace: true })` hides it with `hidden` instead of removing it, so an editor can still read it. Re-calling `hydrate` is safe: processed nodes are skipped, a node whose URL changed is re-done, cards whose source left the DOM are removed.
- **Client checks are a filter, not SSRF protection.** `checkPreviewUrl` refuses non-http(s), credentials, localhost, single-label names, `.local`/`.internal`/`.lan`, private, loopback, link-local, CGNAT and multicast IPv4 literals (URL parsing already folds `2130706433` and `0x7f.1` into dotted form) and IPv6 loopback, ULA, link-local and v4-mapped literals. A public name that resolves to a private address passes. The host's `resolve` must resolve DNS, pin the connection to the checked address, re-check every redirect and cap size and time. The `resolve` contract in types.ts already says it must run on a server.
- **Sanitising.** Everything returned by `resolve` is re-validated on the way in and again in `renderCard`: control and bidi-override characters become spaces, title is capped at 200 characters, description at 400, site name at 100, `extra` at 8 text entries (key 40, value 200). `url`, `imageUrl`, `faviconUrl` must pass `urlAllowed` (`image` kind for the two images) or are dropped; an unsafe `url` falls back to the requested one. A preview with no title, description or image counts as no preview. Cards are built with `textContent` and `setAttribute` only.
- **Cache.** LRU of `cacheSize` (default 100), refreshed on `load` hits and not on `getCached`. A null or failed result is remembered for 60 s (max 500 entries). Concurrent loads of one URL share a promise. `destroy` aborts every in-flight request through its `AbortSignal` and also stops waiting for hosts that ignore the signal; a result that arrives afterwards is dropped.
- **Hover.** Delegated `mouseover`/`mouseout`/`focusin`/`focusout` on the root; `keydown` (Escape) and `scroll` (capture) on the document/window while attached. Mouse opens after `hoverDelayMs`, keyboard focus opens at once. 150 ms grace lets the pointer cross into the card. `(hover: none)` ignores the emulated mouse events of touch but not focus. The popover is appended to `<body>` (so no editor `overflow` clips it), copies `data-atm-theme` from the link's nearest themed ancestor, and is linked with `role="tooltip"` and `aria-describedby` on the link, removed on close. The card inside it is a real link, but a tooltip is not in the tab order; keyboard users already have the link they focused.
- **Embeds.** `matchEmbed` parses with `new URL`, accepts only `https:` without credentials or an explicit port, and runs the provider regex on the normalised href (lower-case, punycode host, trailing dot removed), so `youtube.com.evil.io`, `youtube.com@evil.com` and homographs fail. The generated `src` is parsed again and must be https, credential-free and on the provider's host: built-ins declare `embedHosts` (an extension field on the provider object, not in the shared type); a custom provider without it may only produce a src on the pasted URL's own site (same host or a subdomain of its last two labels). Built-ins: YouTube (served from youtube-nocookie.com, `t`/`start` become `?start=`), Vimeo, Loom, Figma, Google Maps (embed URLs only), Spotify (track/episode 152 px, album/playlist 352 px), CodePen. Twitter/X is left out because its embeds need scripts.
- **Embed iframe.** `sandbox` defaults to `allow-scripts allow-same-origin allow-presentation allow-popups` (no top navigation, no forms), `loading="lazy"`, `referrerpolicy="strict-origin-when-cross-origin"`, `allow` per provider, a `title`, wrapped in `div.atm-embed[data-embed]` with the aspect ratio or fixed height, plus a visible "Open original" link.
- **Not done.** No in-card image proxying (the host's `resolve` should return an image URL it is willing to have fetched by the viewer's browser; `referrerpolicy="no-referrer"` is set). A custom `options.render` result is trusted and not inspected. Spotify album/playlist and track/episode are separate provider entries because `height` is a single number.

## 2026-10-02 — WYSIWYG surface (src/editor/surface.ts, surface/*, dom-to-doc, selection, history, keymap, commands)
- **The DOM is the working copy; markdown is derived.** Each input is coalesced (a microtask; for documents over 20 kB a 120–300 ms pause, since one serialisation costs about 0.4 ms per kB in Chrome) and serialised `DOM → Doc (dom-to-doc.ts) → stringify`; `input` is emitted only when the markdown changed. `setValue` stores the string verbatim and does not emit; `getValue` flushes a pending serialisation. The first edit re-serialises the whole document into canonical form.
- **Render, then decorate.** The surface renders with `renderDom` and then walks the Doc in render order beside the DOM to record what display rendering loses: `data-href` / `data-src` (originals before `links.resolve`), `data-label` on chips, `data-tex` on math, `data-lang` + `data-fence` on `<pre>`, `data-atm-name` + `data-atm-data` on custom syntax, `data-label` on footnote refs and definitions. Links/images the policy refuses are rendered as inert `custom` spans (`__atmlink` / `__atmimg`) carrying the URL as data, so editing never deletes them and they never become live. Tight list items get their inline run wrapped in `<p>` (the `atm-tight` class still decides tightness) so every list item holds blocks. Footnote definitions render at the end; their original position is kept as an anchor attribute (`data-atm-fn`) on the block they followed. Definitions nested inside a quote/list move to the end on the first edit (same meaning).
- **Linear position model (selection.ts).** A DOM point maps to one number: text characters count 1, atoms (chip, math, image, footnote ref, `<br>`) count 1, a trailing placeholder `<br>` counts 0, and each leaf-block boundary counts 1. The same text in a different structure (paragraphs ↔ list items ↔ code-block lines) has the same offsets, so commands and re-renders restore the selection by offset. History stores `[topLevelBlockIndex, offsetInBlock]` paths, never nodes.
- **Structure editing is ours.** `beforeinput` `insertParagraph`, `insertLineBreak`, `deleteContent*` (at block edges, over atoms, across blocks), `historyUndo/Redo`, `insertFromPaste/Drop` and every `format*` are cancelled and done by the surface; ordinary character insertion/deletion inside text stays native (IME, spellcheck, autocorrect). Behaviour: Enter splits (marks continue on both halves); Enter at the end of a heading makes a paragraph, at its start inserts a paragraph above; empty list item → outdent (nested) or paragraph (top level); empty paragraph in a quote → leaves the quote; in a code block a newline, a second Enter on an empty last line exits; in a table the last cell adds a row, other cells move right. Backspace at a block start: heading → paragraph, list item → outdent/paragraph, quote → lifted, empty code block → removed, otherwise merge with the previous block (a rule before it is removed; a table/code block before it only receives the caret). Selecting everything and deleting/typing starts over with one paragraph.
- **Atoms.** Chips, math, images, footnote refs are `contenteditable=false`. ONE Backspace/Delete removes an adjacent atom (chosen over "select first, delete second" because it is what chat-style mentions do); `ChipDefinition.atomic === false` turns the chip back into its text instead. Arrow keys step over atoms; a selected atom collapses to its side. Enter on a selected math atom (or a click) opens its TeX in an inline `<code data-atm-math-edit>`; Enter/Escape/blur/caret-leaving commits and re-renders; an emptied inline formula is removed. Enter on a selected chip calls `ChipDefinition.onClick`.
- **History.** Snapshot stack `{markdown, selection}` (limit 200, typing coalesced within 600 ms). Commands, input rules, paste, drop, task toggles are boundaries (one step each). Before an input rule fires, the literal state is recorded and an exact DOM copy is attached to that entry, so Mod-z right after `## ` brings back the typed `## ` (markdown alone would lose the trailing space). Native undo is never used. `History` is exported for the Markdown pane.
- **Input rules.** Block (space): `#`…`######`, `- * +`, `1.`/`1)` (keeps the start number), `[ ]`/`[x]`/`- [ ]`, `>`. Block (Enter): ```` ```lang ````/`~~~`, `---`/`***`/`___`, `$$`, `| a | b |`. Inline (closing character): `**`/`__`, `*`/`_` (not intraword), `~~`, `` ` ``, `$…$`, `[text](url)`, `![alt](url)`, every `InlineSyntax` with `open`/`close`, bare URL autolink on space/Enter. After a mark rule the next typed text goes after the new element.
- **Commands** (commands.ts) mutate the DOM directly and restore the selection by offset. Toggle semantics: a mark is removed only when every selected character already has it, otherwise it is applied to all; lists toggle off only when every selected block is already that kind of list, a mixed selection converts list types or wraps paragraphs, and a new list merges with an adjacent list of the same kind. Blockquote wraps the selected blocks at the first block's level and toggles off by unwrapping the nearest quote. `link` without an argument returns false so the chrome opens its popover (`exec("link", { url, text? })`; `exec("link", "prompt")` uses `window.prompt`; an empty url unlinks). Additions beyond the brief: `toggleTask`, `codeBlockLang`, `paragraph` on a code block splits it into lines. `table` takes `{ rows, cols }` with `rows` counting the header row (default 3×3). Deleting the header row promotes the first body row.
- **Keymap defaults:** Mod-b/i/e/k, Mod-Shift-x strike, Mod-Alt-0..6 paragraph/headings, Mod-Shift-7 ordered, -8 bullet, -9 quote, Mod-Shift-l task list, Mod-Alt-c code block, Mod-Shift-m math, Mod-Enter toggle task, Mod-\ clear format, Mod-z, Mod-Shift-z / Mod-y. `Mod` follows `navigator.platform` (not the UA string, which test runners and privacy tools override). Bindings match `event.key` and the physical `event.code`. Tab/Shift-Tab indent/outdent in lists and move between table cells; elsewhere Tab is not handled so focus leaves the editor; Escape is never trapped.
- **Paste**: files → `onFiles(files, "paste")`; inside code → plain text; a URL over a selection → link; HTML → `htmlToMarkdown` → parse → insert; plain text that `looksLikeMarkdown` → markdown, otherwise text with one paragraph per line. A single pasted paragraph is inserted inline; several blocks split the current paragraph and merge with both halves. Copy/cut write the selection's markdown as `text/plain` and `renderHtml` of it as `text/html`. Drop: files → `onFiles(files, "drop")` with the caret moved to the drop point; an internal drag moves the content (one step).
- **Whitespace.** The surface sets `white-space: pre-wrap` so browsers type real spaces; soft line breaks inside a paragraph therefore show as line breaks. A non-breaking space next to a space or at a text edge is read back as a space (what browsers insert); one between two characters is kept.
- **Upload placeholder** is a `contenteditable=false` `role=status aria-live=polite` block inserted after the caret's block, never part of the markdown. Its handle has `setProgress`, `remove` and (beyond the contract) `replace(asset)`; `insertAsset` called right after `remove()` inserts at the placeholder's position.
- **Code highlighting** re-runs 250 ms after the last edit in a block (not during composition) and restores the caret by offset. Highlighter output is inserted through a `<template>` (trusted by contract), as the renderer does.
- **Pattern syntax**: `stringify` calls `InlineSyntax.serialize`, so an edit inside a pattern-only node survives; without `serialize`, the original source is written back and such an edit is lost.
- **Untested on devices**: iOS Safari and Android Chrome are covered only by Playwright's Chromium mobile emulation. On Android (Gboard) most keys arrive as composition: during composition nothing is intercepted, so Enter/Backspace at block edges fall back to the browser and the result is repaired by normalisation + dom-to-doc. Firefox and WebKit are not run.

## 2026-10-02 — Editor chrome and composition root (src/editor/create-editor.ts and friends, src/plugins, src/styles/{style,themes,tailwind}.css)
- **One source of truth for the value.** `createEditor` keeps `value` and updates it from the active pane's `input` event payload; `getValue()` never asks a pane. A hidden pane is refreshed on the way in only when its last-loaded string differs, so wysiwyg -> markdown -> wysiwyg without typing never calls `surface.setValue`, and a document the user did not touch is never re-serialised (the string is identical, byte for byte). `setValue` rewrites only the visible pane.
- **Mode switches move the caret by text, best effort.** `alignOffset(source, upto, target, maxSkip)` walks the non-space characters of one string through the other; characters with no counterpart count as syntax (up to 80 of them when the target is Markdown, none when it is the rendered text). It is exact for ordinary prose and approximate around chips and markup that repeats a text character.
- **Chip colour and badge are per (scheme, kind), not per person.** The renderer reads `ChipDefinition.kinds[kind].{color,label}`, so a colour that must survive a reload has to be a function of the `kind` in the stored Markdown. Two ways to supply it: declare `chips: [{ scheme, kinds }]` up front (the demo does; chips already in the document are coloured on load), or let the editor learn it: every `MentionItem` returned by `search` or picked that carries `color` or `badge` registers `kinds[item.kind ?? ""]` in the shared render options if the host did not declare that kind. A learned style only applies to chips rendered afterwards (the chip you just picked, a later paste), never to chips already on screen, and the first item of a kind wins, so two palettes need two kinds (`team-a`, `team-b`). Nothing colour-related is written into the wire format (`attrs._color` was rejected: it would put presentation in the stored Markdown and in every agent's context). People in two systems are one chip of their own kind (`both`) carrying both ids in `refs`.
- **One mention controller for all `mentions` entries.** The controller already takes an options array and picks the trigger closest to the caret; one controller per entry would fight over the same editable's ARIA attributes. `getMentions()` / `onMentionsChange` consider only chips whose scheme is a mention scheme (`"mention"` plus every `MentionOptions.scheme`), unique by `scheme:kind:id`, so a task chip is not a mention.
- **Command contract with the surface (read from `commands.ts`).** `link`: `{ url, text? }` (the chrome sends `url`; `href` is accepted), no argument returns false because the chrome owns the popover. `image`: `{ url, alt }`. `table`: `{ rows, cols }`, rows including the header. `math` / `mathBlock`: the TeX as a string (inline / display). `codeBlock`: optional language string; `codeBlockLang`: language string. `custom:<name>` toggles an inline syntax (the plugin toolbar button tries it first, then `wrap`, then plain Markdown insertion). The textarea implements the same names and argument shapes, so the chrome drives both panes with the same calls; `wrap {open,close}` and `unlink` are extras.
- **Chrome commands live in the same map as plugin commands.** `link`, `image`, `table`, `math`, `codeLanguage` (popovers, only when called without arguments), `attach` and `emoji` are entries in the `customCommands` map handed to the surface. Because a surface runs its own built-in of the same name first, shortcuts are resolved in `beforeKeyDown` against the shared keymap (`createKeymap`, the surface's own table) and routed to `editor.exec` whenever the command is in that map. That is also how a host's `registerCommand("bold", …)` wins on the keyboard.
- **`beforeKeyDown` contract.** When it returns true, the PANE (surface or Markdown pane) calls `preventDefault` and `stopPropagation` itself; a caller never has to. Documented in `pane-types.ts`.
- **`aria-expanded` and `aria-haspopup` are never set on the editable.** The editable is `role="textbox"`, which does not support them (axe: critical). `mentions.ts` sets only `aria-controls` and `aria-activedescendant` while the menu is open (verified with axe in Playwright); the MutationObserver workaround is deleted.
- **Toolbar.** `role="toolbar"` is the inner element; the row (slot `toolbar`) also holds the mode switch and, in `bottom-bar`, the `actions` slot. Roving tabindex, `aria-pressed` from `pane.isActive`, `aria-disabled` from `pane.can` (not while the editor has no focus, because a pane without a selection answers false for everything), refreshed on coalesced `selection` events. Mouse down is cancelled so a click never moves the selection; every command returns focus to the editor. Overflow is a pure function (`computeOverflow`) driven by a ResizeObserver, with a "more" menu. Tooltips: native `title` for hover, a custom one on keyboard focus, `aria-keyshortcuts`. Shortcut hints come from `DEFAULT_KEYMAP` plus the host's keymap, never a second table; platform detection uses `navigator.platform` first, like `isApple()`, so a hint and its key agree.
- **Layouts.** `LayoutDefinition.build` receives the host's slot classes in `classes` (an empty string for slots it left out); built-in layouts append them AFTER their own `atm-*` classes. Built-in layouts are `RuntimeLayout`s: the same plus `defaults` (toolbar position, status bar, mode), `attach(host)` (bubble) and `onKeyDown` (Mod-Enter submit in bottom-bar, Alt+F10 into the bubble). A custom layout without those still works. `bottom-bar` fires `submit` (a `CustomEvent`, `detail: { value, editor }`, bubbles) on the root; `actions` exists only there. The bubble toolbar is last in DOM order (Tab from the editor reaches it), placed above the selection and flipped below its end when there is no room (so it never covers the start), kept visible while focus is inside it (the editor reports no selection then), and Escape hides it until the selection changes.
- **Popovers** are `role="dialog"`, mounted inside the editor root (so theme variables reach them), `position: fixed` from `getCaretRect()` with a flip, Tab-trapped, Escape (stopped from propagating) closes and restores the saved selection and focus. The link and image URLs go through `normalizeLinkInput` (control and zero-width characters stripped first, as browsers do, so `java<TAB>script:` is seen as what it is) and `urlAllowed` before anything is applied.
- **Slash menu** hooks `beforeKeyDown` / `afterInput`, never opens in `pre`/`code`, deletes the typed `/query` with a Range and tells the surface with a synthetic `input` event before running the command. It scrolls by wheel and arrow keys, not native overflow, on a fine pointer: a scroll container that focus never enters fails axe's `scrollable-region-focusable`, and the ARIA combobox pattern forbids moving focus into the list.
- **Uploads.** `validateFile` -> placeholder -> handler (`signal`, `onProgress`, `kind`) -> `urlAllowed(url, upload.urls ?? links, kind)` BEFORE the asset is inserted -> `insertAsset`. Concurrent. A result that arrives after a mode switch lands in the pane that is visible then. `destroy()` aborts every controller and ignores late results and AbortErrors. In Markdown mode the text `![alt](url)` / `[name](url)` is inserted at the caret (brackets escaped, URLs with spaces or parentheses wrapped in `<>`).
- **Emoji.** `emoji.open` returning anything but `false` means the host handled it; otherwise the editor is focused and a polite status shows `labels.emojiHint` with `{shortcut}` replaced (macOS `Ctrl+⌘+Space`, Windows `Win+.`, Linux `Ctrl+.`, anything else "your system's emoji shortcut").
- **Labels.** `DEFAULT_LABELS` covers `EditorLabels`. Strings the chrome needs that are not in that type live in `EXTRA_LABELS` (apply, cancel, popover field names, rejection reasons, `lengthLimit`, …); the merge is key-agnostic, so a host can already override them. Promoting them to the type is an additive change for the contract owner.
- **Theme.** `light`/`dark` set `data-atm-theme`; `auto` resolves `prefers-color-scheme` in JS and follows changes; a token object sets inline `--atm-*` (values that could end a declaration are dropped). With no `theme` option the editor follows a theme an ancestor already set, else the OS, so the chrome agrees with `highlight.css`. `themes.css` selectors are doubled (`:root:root`, `[data-atm-theme="x"][data-atm-theme]`) because `surface.css` also declares a chip palette on `:root` and on `.atm-surface`; `style.css` hands the theme's palette back with `--atm-chip-N: inherit` on `.atm .atm-surface`. Palette, text, muted, accent and ring colours of all five themes are asserted against WCAG AA in `chrome-theme.test.ts`, including the badge formula `surface.css` uses (80% colour + 20% fg text on a 14% + 22% tint). Themes `highlight.css` does not know (sepia, slate, contrast) carry their own `--atm-tok-*`; plugin CSS reads `--atm-mark-bg|fg` and `--atm-callout-*` from the theme, never a `dark` selector.
- **CSS build.** `scripts/copy-css.mjs` inlines `@import "./x.css"` recursively, once per file, in the order themes, surface, highlight, link-preview, then `style.css`; a missing file is skipped with a warning. `tsup` has `clean: true`, so run it BEFORE `copy-css` (the build script does).
- **Plugins** are plain data (`definePlugin` and friends are identity helpers), tree-shakable named exports, CSS through the `css` field (ref-counted per document, removed with the last editor that used it).
- **Size.** Superseded: see "2026-10-02 — Size budget and lazy chunks" below.
- **Link previews, embeds, mention slot classes and split-preview chip clicks are wired**: see the sections below.

## 2026-10-02 — Feature plugins (src/plugins/{find-replace,drafts,toc,text-style,smart-typography,shortcodes}.ts, styles/plugins.css)

Every one is a `createXPlugin(options)` factory returning a plain `Plugin`, zero dependencies, using only the public `EditorInstance`, `Plugin` fields and the DOM `editor.element` exposes (`.atm-surface` for WYSIWYG, the `textarea` for Markdown mode, `.atm-preview` for the split preview, `.atm-statusbar`, the `atm-readonly` class). Each exports its pure logic (match finding, slugs, the typing rule, the draft envelope, ...) so it is unit-tested without a DOM, and its CSS string (`FIND_REPLACE_CSS`, `DRAFTS_CSS`, `TOC_CSS`, `TEXT_STYLE_CSS`, `SHORTCODES_CSS`). `src/styles/plugins.css` is those strings concatenated; `test/plugins/css.test.ts` fails if they drift.

- **The Markdown pane is loaded lazily**, so in Markdown mode the `textarea` may not exist for a moment. Plugins never assume it: find-replace retries for up to 5 s after a mode switch, the others look it up when they act.
- **find-replace.**
  - Matching is on text *runs*: one run per block, split at `<br>`, atoms (`contenteditable=false`, chips, math) and, with `includeCode:false`, code. A match can span bold/italic runs but never blocks. Regex mode matches within one block (WYSIWYG) or one line (Markdown).
  - Safety has three layers because JavaScript cannot interrupt a running regex: (1) a heuristic refuses the classic exponential shapes (a group holding one quantified atom that is itself quantified: `(a+)+`, `(.*)*`, `([a-z]+)*`, `(?:x*)+`); (2) a run is cut at 50,000 characters; (3) the scan stops at 5000 matches (`5000+` is shown) or 150 ms between matches. A pattern that is slow without being one of those shapes can still stall one `exec`; the heuristic is not a proof.
  - Highlights use `CSS.highlights` (`atm-find`, `atm-find-current`; the current match is kept out of `atm-find` so each can be styled alone). Without it, overlay boxes in `.atm-find-overlay`, a sibling of the surface, so nothing can reach the stored Markdown. `highlightApi:false` forces the overlay.
  - Replace goes through `selection range + editor.insertText`. **Replace all in WYSIWYG edits the matched text nodes directly and dispatches one `input` event**, because a loop of `insertText` calls is N history entries and the public API has no transaction. An empty `insertText("")` before and after ends the typing group on both sides, so typing straight after is its own undo step. Replacements containing a line break (only possible in regex mode with `\n`) take the slow path, one `insertText` per match. In Markdown mode Replace all is one `insertText` over the span from the first match to the last.
  - Navigation never moves the document selection while the focus is in the bar (that can pull focus out of the input in some browsers); only Escape selects the current match and returns focus. The bar and the replace controls keep the focus through an edit.
- **drafts.** The envelope is `{v:1, savedAt, value}`; an unknown `v` is dropped, not migrated. While the restore question is open nothing is written, otherwise the first keystroke would overwrite the draft being offered. Another tab's change raises a banner (Sync / Ignore) and is never applied silently. The status is a `CustomEvent` (`atm-draft-status`) on `editor.element` plus `onStatus` because `EditorEvents` is closed; `setValue` (restore, sync) does not fire `onChange`, so `onRestore` exists. Destroy flushes a pending save (data protection); `draft:clear` cancels it first.
- **toc.** The block is `::: toc` with optional `min=` / `max=`. The generated list is **not in the editor's light DOM**: the block is `contenteditable=false` and the list is rendered into its shadow root, because the surface serialises its DOM to Markdown and anything in the light DOM would be stored. In the split preview (read-only, re-rendered by the editor) the list is plain DOM. Headings carry `data-atm-slug` in the editor and `id` in a view that was passed to `hydrateToc(root, doc)`; static HTML from `renderHtml` cannot generate content, so a host's read-only view must call it. Slugs are assigned over *all* headings so a level filter never changes an id; empty headings consume none. Dedupe is `-2`, `-3`; a slug that collides with another heading's own text gets a further suffix.
- **text-style.** `[text]{.c-red}` / `{.bg-yellow}` / `{.c-red .bg-yellow}` is a pattern syntax built from the allow-list, so an unknown class does not match and stays text (and stringify escapes its brackets). The rendered element carries `data-ts=".c-red"` and the stylesheet selects on `[data-ts~=".c-red"]`; no class or style is ever copied from the Markdown. **The span body is literal text (`nested:false`)**: `InlineSyntax.serialize` receives plain text, and the surface refreshes `_raw` from it on every sync, so nested formatting would silently disappear on the first unrelated edit. Applying a colour to a selection therefore applies it to the selection's plain text. The palette keeps >= 4.5:1 contrast on white and sepia (text) and on the dark themes (dark set). Underline is `++text++` and shares its marker with the `kbd` plugin: enable one.
- **smart-typography.** WYSIWYG only; the Markdown source is verbatim. Rules are a pure function of the text before the caret (`typographyRule`). Dashes (both `--` and `---`) never convert when the line so far holds only spaces, `|`, `:`, `>` or `-`: `--` must stay available to reach `---` (a rule) and `|---|---|` is a table. A quote opens after start/space/opening punctuation and closes otherwise; a `'` after a letter is `’` unless a single quote is still open on the line. Fractions convert when the character *after* them is typed (so `1/20` is safe) and multiplication on the second digit (`0x1F` is left alone); neither is revertible. The surface inserts some characters itself and cancels `beforeinput` (the first character of an empty block), so no `input` event follows: the plugin also listens for a `beforeinput` that was cancelled. Revert is a capture-phase Backspace that replaces the run with what was typed through `insertText` (one step).
- **shortcodes.** Built on `createMentionController` with trigger `:` (public options only). Menu in WYSIWYG; in Markdown mode the closing colon and `insertShortcode` work without a menu. An unmatched query shows the controller's "no results" row, as for @mentions. Recent names are kept through `storage` (default `localStorage`, guarded) and rank only inside the same match class: exact > prefix > word start > substring.

## 2026-10-02 — Size budget and lazy chunks (src/editor/lazy-chunks.ts, scripts/size.mjs, tsup.config.ts)
- **Budget decision.** The editor entry has a TARGET of 48 kB gzip and an ENFORCED ceiling of 62 kB; measured 60.2 kB (bundled). The other budgets: parser 14 kB (10.98), render 14 kB (12.07), math 5 kB (4.96, almost no headroom), each language 2 kB, each lazy chunk 15 kB. The 48 kB target is printed as a warning on every run so the gap stays visible. The remaining 60 kB is the typing engine (surface, selection, history, dom-to-doc, commands), the parser, the renderer, the toolbar and the composition root. Making more of it lazy would make typing or commands asynchronous, or would only move bytes into a chunk that is always requested at startup, which games the metric without helping a user. Closing the gap needs a different design (asynchronous commands), not another cut.
- **Two measures.** "bundled" = gzip of the entry plus its static chunks concatenated (what a bundler user ships; ENFORCED) and "files" = the sum of each file's own gzip (what a browser downloads with no bundler; larger by about 4 kB because each small file pays its own header). `size.mjs` minifies every `dist` file with esbuild before measuring, because `dist` keeps its whitespace (next point).
- **Lazy chunks.** `popovers`, `slash`, `mentions`, `uploads`, `markdown-pane`, `math`, `paste` and `rich-links` are `import()`ed through `chunks.<name>` in `lazy-chunks.ts`. Each has `get()` (the module once loaded, so later use is synchronous) and `load()` (retries after a failure). `size.mjs` has a LAZY CONTRACT check: each must exist as a lazy chunk and the entry must not load it statically. Behaviour while a chunk is loading: the popover holds the characters typed meanwhile and replays them into its first field (or into the pane if the load fails); `LazyMarkdownPane` queues focus, insertText, setValue and selection; math shows `<code class="atm-math-src">` and calls `Surface.rerender()` when the renderer arrives; slash loads when `detectSlash` matches the text before the caret; mentions load at attach with a catch-up input; paste converts HTML asynchronously and falls back to plain text. A failed download leaves the editor intact. `preloadChunks()` loads all of them; the unit-test setup calls it once per file so tests stay synchronous, and cold behaviour has its own tests (`vi.resetModules()`).
- **Main entry slimming.** `index.ts` no longer re-exports math, uploaders, mentions, paste, link-preview, embeds or the ready-made plugins. New subpaths: `plugins`, `mentions`, `paste`, `link-preview`, `embeds`. Breaking for 0.x consumers, and recorded in the changelog.
- **Tree-shaking.** tsup runs with `minify: false` and esbuild `minifyIdentifiers` + `minifySyntax` on, `minifyWhitespace` off: whitespace-minified output drops `/* @__PURE__ */`, and the consumer's bundler needs those comments to remove unused top-level calls (icon tables, `lazy(...)` registrations). The icon table, the lazy registrations, the REFDEF/TITLE constants in `block.ts` and `allVars()` are written so no module-level call remains unmarked. `package.json` `sideEffects` is `["**/*.css"]`. `check-package.mjs` bundles probes: `definePlugin` alone is 0.06 kB, `parse` 7.7 kB, `renderHtml` 11.5 kB. esbuild with `splitting` leaks about 9 kB (it splits before tree-shaking); Rollup and webpack do not.
- **`parse` lives in `parser/parse.ts`** so `render` imports the parser without `stringify`.
- **CSS minifier.** `scripts/css-minify.mjs` (about 60 lines, no dependency) writes `dist/style.min.css` (36.4 kB against 49.2 kB). It strips comments and whitespace, keeps strings and `url()` intact and never touches `calc()`/`clamp()` operators. The test compares rule structure rather than jsdom declarations, because jsdom's CSS parser drops `color-mix(...)` after spaces following commas are removed.
- **Scaling-ratio timing tests.** Wall-clock thresholds failed on a busy machine. `test/helpers/scaling.ts` measures n and 4n inputs, takes the best of several runs, retries up to three times and asserts the ratio stays under `LINEAR_MAX_RATIO` (10); a 30 s backstop and a 30 s `testTimeout` catch only a true hang. The new tests found a real quadratic: the inline `"\n"` case rescanned the whole buffer with `/ +$/`; now a tail loop.

## 2026-10-02 — Rich links in the editor (src/editor/rich-links.ts, render/embed.ts)
- **Loaded only when `linkPreview` or `embeds` is set.** A scan runs after edits settle (350 ms) and once at attach: a paragraph holding only a link whose text equals its address gets `data-atm-standalone-link` (only when the caret is not on that line); `controller.hydrate` puts the card INSIDE the paragraph, after the link, as `[data-atm-preview-card]`.
- **Cards are not content.** The position model skips `[data-atm-preview-card]` (`isSkip`; `isAtom` excludes skipped nodes), dom-to-doc drops cards inline and as blocks, and `normalizeInline`, `sameShell` and `removeEmptyInline` ignore them, so a card can never be serialised into the Markdown and never moves the caret offset. The surface renders with `linkPreview: undefined` so the renderer does not also emit the paragraph marker (that produced two cards).
- **Embeds are atomic blocks.** `matchEmbed`, `embedSpec` and `findStandaloneUrl` live in `render/embed.ts`; `embedOf()` is the single predicate used by the renderer and `surface/render.ts collect()` so link pairing stays aligned (an embed paragraph has no link). An embed is `contenteditable=false` with `data-atm-embed-url` holding the ORIGINAL URL; dom-to-doc turns it back into a paragraph with a bare-URL link. Embeds are top-level only (a `nest` counter in the renderer) and respect the link policy.
- **Convert to link rewrites the line as `[host](url)`**, because a link whose text differs from its address is not a standalone URL; the choice therefore survives a reload (a flag on the DOM would not). The caret is placed at the end of the new paragraph.
- **Hover for keyboard users.** Links inside a contenteditable are not focusable, so when the caret enters a link, `rich-links` dispatches `focusin` (and `focusout` when it leaves) at it, which is what the hover controller already listens to.
- **Split preview.** The renderer emits markers and embeds; `previewRendered()` only hydrates. A click delegate on the preview pane calls `ChipDefinition.onClick`.
